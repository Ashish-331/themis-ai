---

### Does Git history reveal that code was written by AI?

Technically, pure `git` only records:
* Commit hash, author/committer name & email, timestamps, commit messages, and the diff.

Git itself has no built-in "AI detector". However, git histories often leak AI usage in subtle ways:

#### 1. Auto-generated Commit Trailers & Attribution
Many modern AI coding tools automatically attach trailers or metadata to commit messages:
* **Co-authored-by tags:** E.g., `Co-authored-by: Claude <noreply@anthropic.com>` or `Co-authored-by: GitHub Copilot <...>`
* **Tool signatures:** Commit messages generated by AI tools often follow distinct patterns, like `feat: add auth service (generated with Cursor)` or standard template phrases.

#### 2. Commit Cadence & Velocity (Timestamp Analysis)
* Human development usually involves iterative commits: creating files, breaking things, fixing typos, and tweaking logic.
* If a repository has commits 2 minutes apart introducing **800 lines of complex, production-grade boilerplate or architecture with zero intermediate bugs or commits**, that timeline is an immediate giveaway to experienced engineers.

#### 3. Stray Configs & IDE Artifacts
AI tools often create local config files that accidentally get committed if they aren't in `.gitignore`:
* `.cursor/` or `.cursorrules`
* `.windsurf/`
* `prompts/`, `.claude/`, or workspace state files.

#### 4. Inline AI Comments & Artifacts
AI-generated code often leaves telltale signs in the code itself:
* Comments like:
  ```python
  # Here is the function to process payments...
  # Note: Replace this placeholder with your actual API key
  # In a production environment, you should consider...
  ```
* Overly verbose docstrings or academic-style comments that human developers rarely write during a 48-hour hackathon.

---

### What judges actually care about

1. **Working Execution:** Does the project actually run, deploy, and work as demonstrated in your 3-minute video?
2. **AWS Integration:** Did you genuinely integrate AWS cloud/open-source tools rather than just having a flashy front-end?
3. **Your Understanding:** If your project gets shortlisted for the **Amazon fast-track interview**, Amazon engineers will interview **you** directly. They will grill you on the architecture, trade-offs, edge cases, and why you chose specific designs. If you can explain every piece of your codebase thoroughly, using AI to accelerate your building will be seen as a strength, not a weakness.

### 🤖 Assistant

Depending on whether you are using the **Antigravity CLI (`agy`)** in your terminal or the **Antigravity IDE**, here is how you can navigate to or reference a file:

---

### 1. In Antigravity IDE (VS Code based)
* **Quick Open File:** Press **`Ctrl + P`** (Linux/Windows) or **`Cmd + P`** (macOS), then type part of the file name and press Enter.
* **File Explorer:** Press **`Ctrl + Shift + E`** to toggle the sidebar file tree.
* **Reference a file in the AI Chat:** Type **`@`** in the chat box (e.g., `@filename.py`) to search, autocomplete, and attach that file directly into the agent's context.

---

### 2. In Antigravity CLI (`agy`)
* **Reference a file in a prompt:** 
  * Type **`@<path-to-file>`** (e.g., `@src/index.js` or `@README.md`).
  * Or simply type/paste the relative or absolute path directly in your prompt.
* **Tell the assistant:** You can simply type:
  ```text
  show me the contents of <filename>
  ```
  or
  ```text
  view /path/to/file
  ```
  The agent will use its file-viewing tools to open and inspect it for you.

---

### 3. Switching Workspaces / Directories in `agy`
If you want `agy` to work in a different folder (for example, on your Desktop or in another project):
1. **From your terminal shell:** Exit `agy` (`Ctrl + D Ctrl + D` or `/exit`), change to that directory, and run `agy`:
   ```bash
   cd ~/Desktop
   agy
   ```
2. **Include extra directories on startup:**
   ```bash
   agy --add-dir /path/to/other/folder
   ```
